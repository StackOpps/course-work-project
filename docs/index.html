Automation level Partial — by design Backup and restore-testing run entirely on AWS-managed schedules with no human step. The recovery workflow runs fully unattended once dispatched (Terraform re-apply, RDS restore, smoke check, DNS cutover, result recorded). Only the dispatch itself is manual — a deliberate one-click human decision point before cutover, not an automation gap.
Backup protection Configured, not enabled Vault Lock (governance mode) is implemented in Terraform for both the primary and DR vaults, but disabled in the running testbed because it's torn down on a recurring schedule to bound cost, which needs recovery points deletable on demand.
Monitoring & auditability Verified CloudWatch alarms on EC2 status checks, RDS free storage, and AWS Backup job/copy/restore state, alerting a per-region SNS topic. A single multi-region CloudTrail trail logs every backup, restore, and configuration change.
Cost Bounded, not instrumented The DR region holds only a backup vault during normal operation, not standing infrastructure, and the whole testbed is destroyed between test runs to bound spend — but no live cost figure is pulled onto this dashboard yet.
Infrastructure reproducibility Verified Every drill re-applies the exact Terraform that provisions the primary environment against the DR region instead of a separate recovery procedure, and the primary environment itself is destroyed and rebuilt from code on a recurring schedule.
